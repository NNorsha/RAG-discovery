# Prompt Engineering 要点

## 基本原则

- 指令具体:写清任务、输入、输出格式和约束,少说"尽量""最好"。
- 给足上下文:模型不知道你的默认假设,把背景写进 prompt。
- 分步思考:复杂任务拆成步骤,或要求模型先分析再作答。

## Few-shot

给 2 到 5 个输入输出示例,模型会模仿示例的格式和风格。
示例要覆盖典型情况和边界情况,示例的顺序有时也会影响结果。

## 结构化输出

要求模型输出 JSON 并给出字段说明,便于程序解析。
更稳的做法是使用 API 的 JSON mode 或 function calling,从协议层保证格式,
而不是靠 prompt 祈祷模型守规矩。

## 控制幻觉

- 明确授权"不知道":告诉模型"资料不足时直接回答不知道"。
- 要求引用来源:每句话标注出自哪条资料,便于人工核对。
- 降低 temperature(0 到 0.3)让输出更确定。

## 评估

Prompt 的每次改动都要用固定测试集回归:
准备 20 到 50 个代表性问题和标准答案,改完 prompt 跑一遍对比准确率,
避免"感觉变好了"式调参。
